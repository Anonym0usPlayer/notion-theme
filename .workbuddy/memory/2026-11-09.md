## 修复：平滑光标点击代码块顶部出现黑色竖线
- 现象：开启平滑光标后点击代码块顶部，覆盖层在工具栏位置画出竖线；块边界时还可能被拉成长竖线。
- 根因：`js/modules/smoothCaret.js` 的 `getCaretInfo` 只校验选区位于 `.protyle-wysiwyg[contenteditable="true"]` 内，未排除 `contenteditable="false"` 的 `.protyle-action` / `.protyle-attr` 等不可编辑区域；浏览器点击工具栏时仍会把选区落在其中文本节点上。此外 fallback 直接使用 `range.getBoundingClientRect()`，块边界会返回覆盖整块的矩形。
- 改动：
  - 选区锚点最近的 `[contenteditable]` 非 `true` 时直接隐藏覆盖层。
  - 新增 `isCaretSizedRect`，以 computed lineHeight 为基准统一校验所有候选矩形（宽度异常或高度超过 1.8 行即拒绝），块级矩形交给空块兜底。
  - 兜底分支：`lineHeight` 为 NaN 时不再回退到整块高度；命中多行容器（`height > 2.5 行`）直接隐藏，避免光标落在编辑器左上角。
  - `theme.css` 的 `caret-color: transparent` 扩展到 `:is([contenteditable], .hljs, .hljs *)`，防止代码块自带 caret-color 声明导致原生黑色插入符外露。
- 验证方式：用无头 Chrome 构造思源代码块 DOM，注入真实模块源码（`export` 去掉后内联），对 9 个选区场景做修复前/后对照。工具栏 3 个场景与"选区落在代码块容器"由画竖线变为隐藏；代码行首、普通段落、空行内代码、分割线保持原有表现；空表格单元格在模拟 DOM 下前后一致。
- 环境：仓库 `node_modules` 原本是 Windows 平台二进制（esbuild/lightningcss 缺 darwin-arm64），`npm install` 补装后 `npm run build` 全链路通过，产物在 `dist/`；`package-lock.json` 被 npm 同步版本号，已还原。

## 修复：平滑光标覆盖层盖住菜单选项
- 现象：菜单/联想框弹出时，块内闪烁的覆盖层压在菜单选项文字上。
- 根因：`.savor-smooth-caret` 挂在 `document.body` 且 `z-index: 9999`，高于思源菜单、对话框等浮层。
- 改动：
  - `theme.css`：覆盖层 `z-index` 降为 `100`（低于浮层，仍高于编辑器常规内容）。
  - `js/modules/smoothCaret.js`：新增 `hasFloatingLayer()`，检测 `#commonMenu` / `.b3-menu` / `.hint--menu` / `.protyle-hint` / `.protyle-toolbar` / `.protyle-util` / `.b3-dialog--open`，按 `fn__none`、display/visibility/opacity 与实际渲染矩形判可见；有浮层时 `updateCaret` 直接隐藏覆盖层。
  - 为保证弹出/收起及时刷新，新增 capture 阶段的 `pointerdown` / `keydown` 监听与 `document.body` 直接子节点 `childList` 的 MutationObserver（不开 subtree）；`disableSmoothCaret` 中全部清理。
- 验证：无头 Chrome 内联真实模块源码与 `theme.css` 中的真实规则，11 个场景全部通过（菜单弹出/移除由观察器自动触发、fn__none、display:none、斜杠菜单、对话框、常驻隐藏工具条不误判、关闭清理、z-index=100）；`npm run build` 通过。

## 修复：非融合模式下新建文档按钮贴住最后一个标签
- 现象：非融合模式下标签页与右侧「新建文档」按钮几乎贴在一起，按钮视觉上压住最后一个标签右边缘一小块。
- 根因：思源原生 CSS（本机 `/Applications/SiYuan.app/.../stage/build/desktop/base.7fab0befdc6d4eee2d9e.css`）给右侧操作区 `ul.layout-tab-bar--readonly` 设置 `margin-left: var(--b3-ui-tab-actions-margin-left, -8px)`，紧凑模式为 -7px；主题此前只在旧 merge 模式与独立窗口模式给 `[data-type="new"]` 加过 margin-right，未抵消这个负外边距。
- 改动：`style/module/tab-bar.css` 新增 `:root:not([savor-tabbar]) body:not(.body--toolbar-hide,.body--mobile) .layout__center .fn__flex-column>.fn__flex>.layout-tab-bar--readonly { margin-left: 2px; }`。用 `:root:not([savor-tabbar])` 排除垂直页签与已废弃的 merge 模式，用 `body:not(...)` 排除融合与移动端，避免改变这些模式原有布局。
- 验证：无头 Chrome 注入思源原生 CSS 全量 + 构建后的 `dist/theme.css`，按真实 DOM 结构测量。非融合默认由 `margin-left:-8px`/间距 1px 变为 `2px`/间距 11px；紧凑模式 2px / 8px；融合、垂直页签、移动端均保持原生 -8px 未被改动。`npm run build` 通过，产物已更新。
